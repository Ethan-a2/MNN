Tensor Memory Layout: NC4HW4

Special memory format for SIMD optimization on ARM/x86 backends

Problem: Standard NCHW Layout

// NCHW: channels not aligned for SIMD Tensor shape: [N, C, H, W] Memory layout: N0: C0 C1 C2 C3 C4 C5 C6 C7 C8 ... ^ ^ ^ | | | SIMD SIMD SIMD load 4 load 4 load 4 channels channels channels (non-contiguous)

SIMD registers cannot efficiently load non-contiguous channel data

Solution: NC4HW4 Layout

// Channels packed by 4 for SIMD Tensor shape: [N, C, H, W] (logical) Memory layout (C=32): N0: C0-3 H0 W0 | C4-7 H0 W0 | C8-11 H0 W0 | C28-31 H0 W0 ^^^^^^^^ ^^^^^^^^ ^^^^^^^^ ^^^^^^^^ SIMD reg 1 SIMD reg 2 SIMD reg 3 SIMD reg 4 N0: C0-3 H1 W0 | C4-7 H1 W0 | ... (next height row)

Each SIMD register loads 4 contiguous channels → optimal throughput

// Enum definition in Tensor.hpp enum class DimensionFormat { TENSORFLOW = 0, // NHWC CAFFE = 1, // NCHW CAFFE_C4 = 2 // NC4HW4 (optimized) };

Shape Inference System

Static shape computation at model load time for memory efficiency

// Source: source/shape/ShapeConv.cpp void ShapeInferenceConv2D(const Op* op, const std::vector<Tensor*>& inputs, const std::vector<Tensor*>& outputs) { const Conv2DCommon* common = op->main_as_Conv2DCommon(); const Tensor* input = inputs[0]; Tensor* output = outputs[0]; // Extract dimensions auto inputShape = input->buffer(); int batch = inputShape->dim[0].extent; int inChannels = inputShape->dim[1].extent; int inHeight = inputShape->dim[2].extent; int inWidth = inputShape->dim[3.extent; // Convolution output formula int kernelH = common->kernelY(); int kernelW = common->kernelX(); int strideH = common->strideY(); int strideW = common->strideX(); int padH = common->padY(); int padW = common->padX(); int outHeight = (inHeight + 2*padH - kernelH) / strideH + 1; int outWidth = (inWidth + 2*padW - kernelW) / strideW + 1; int outChannels = common->outputCount(); // Set output shape auto outputShape = output->buffer(); outputShape->dim[0].extent = batch; outputShape->dim[1].extent = outChannels; outputShape->dim[2].extent = outHeight; outputShape->dim[3].extent = outWidth; }
Key Insight: Shape inference runs once during model loading, not at every inference. This allows pre-allocation of all tensor memory upfront, eliminating runtime allocation overhead.
Dynamic Shapes

While MNN supports dynamic dimensions, shape inference computes the minimum required tensor size. Actual runtime dimensions must be within inferred bounds.

Shape Propagation

Inferred shapes propagate through the graph. Downstream ops use upstream output shapes as their input shapes, establishing complete memory requirements.

Memory Management: BufferAllocator

Centralized memory pool for tensor allocations, minimizing malloc/free overhead

// source/core/BufferAllocator.cpp class BufferAllocator { public: Buffer allocate(int size, int alignment = 128) { // Round up to alignment int alignedSize = ((size + alignment - 1) / alignment) * alignment; // Check if we have a free block of sufficient size for (auto& block : mFreeList) { if (block.second >= alignedSize) { return splitBlock(block, alignedSize); } } // Need to allocate more memory return allocateMore(alignedSize); } void free(const Buffer& buffer) { // Return to free list (coalescing adjacent blocks) mFreeList.insert({buffer.offset, buffer.size}); coalesce(); } private: std::map<int, int> mFreeList; // offset → size std::vector<void*> mBlocks; // allocated memory blocks; };

Allocation Strategy

  • First-fit allocation from free list
  • Block splitting for partial allocations
  • Coalescing adjacent free blocks on free
  • Chunked growth: allocate in large chunks (e.g., 4MB)

KVCache: Key-Value Cache

Critical optimization for LLM inference avoiding recomputation of past attention keys/values

Without KVCache (Naive)

// Each token: recompute ALL previous tokens for position = 0 to N: compute Attention(Q, K[0:N], V[0:N]) // O(N²) grows! Time complexity: O(N³) for N tokens Memory complexity: O(N) for activations

With KVCache (Optimized)

// Cache K[0:N-1], V[0:N-1] after first N tokens for position = 0 to N: K[position], V[position] = compute_KV(position) store in cache for position = N to M: Attention(Q[position], cacheK[0:position], cacheV[0:position]) K[position], V[position] = compute_KV(position) append to cache Time complexity: O(N² + N*(M-N)) ≈ O(N*M) Memory complexity: O(N) for cache
🔍 KVCache Implementation Details
// kvmodule.hpp: KV cache structure struct KVCache { Tensor mKey; // [numLayers, numHeads, pos, headDim] Tensor mValue; // [numLayers, numHeads, pos, headDim] int mCurPos = 0; // Current position in cache int mMaxPos = 4096; // Max sequence length }; // On each token: forwardOne(token, KVCache& cache) { // 1. Compute Q, K, V for current token auto QKV = mAttention->computeQKV(token, cache.mCurPos); // 2. Write K, V to cache (at position mCurPos) cache.mKey->setTo(QKV.key, cache.mCurPos); cache.mValue->setTo(QKV.value, cache.mCurPos); // 3. Attention: read entire cache auto attn = computeAttention(QKV.query, cache.mKey, cache.mValue); cache.mCurPos++; // Advance position }

Performance Optimization: Winograd Algorithm

Reduces convolution complexity from O(n²) to ~O(n) for small kernels (3×3, 5×5)

Standard Convolution

// Output pixel at (i,j): for k = 0 to K-1: // K = kernel size² × inChannels for c = 0 to C-1: sum += input[i+kH][j+kW][c] * weight[k][c];

Complexity: O(K·C) per output pixel

Issue: High memory access, redundant computation

Winograd Transform

// Transform: G * input * G^T (G = Winograd matrix) inputTransformed = G * input * G^T; weightTransformed = G * weight * G^T; // Element-wise multiply (much faster!) outputTransformed = inputTransformed ⊙ weightTransformed; // Inverse transform output = G^T * outputTransformed * G;

Complexity: O(n) transforms + O(n) multiply

Speedup: 2-3× for 3×3 convolutions

// Source: source/math/WinogradConv2D.cpp bool WinogradConv2D::compute() { const int tileSize = 4; // 4×4 tiles for (int y = 0; y < outputHeight; y += tileSize) { for (int x = 0; x < outputWidth; x += tileSize) { // 1. Load input tile (2×2 padding → 4×4 tile) auto inputTile = loadInputTile(x, y); // 2. Transform input & weights auto U = transformInput(inputTile); // G * input * G^T auto V = transformWeights(mWeights); // G * weight * G^T // 3. Point-wise multiply (core Winograd) auto M = elementwiseMultiply(U, V); // 4. Inverse transform auto outputTile = inverseTransform(M); // 5. Store to output storeOutputTile(outputTile, x, y); } } }

Quantization: INT8 & FP16

Reducing model size by 50-75% with minimal accuracy loss

INT8 Quantization
// Quantization formula float -> int8: scale = (max - min) / 127 zero_point = -round(min / scale) int8_t q = round(f / scale) + zero_point; int8 -> dequantize: float f = (q - zero_point) * scale;

Benefits: 4× smaller, faster integer arithmetic

FP16 Quantization
// Half-precision (16-bit float) struct FP16 { uint16_t data; }; // Convert FP32 to FP16 FP16 float_to_fp16(float f) { uint32_t x = *((uint32_t*)&f); uint16_t h = ((x >> 16) & 0x7fff) | ((x >> 16 - 23 + 127) & 0x8000); return *(FP16*)&h; }

Benefits: 2× smaller, hardware FP16 support (ARM, GPU)

// 1. Calibration: collect activation ranges for (auto& sample : calibrationDataset) { auto activations = model.forward(sample); for (auto& act : activations) { minVal = std::min(minVal, act.min()); maxVal = std::max(maxVal, act.max()); } } // 2. Performance Optimization Checklist

Best practices for getting the most out of MNN

Model-Level
  • Use fixed input sizes (MNN_BUILD_MINI)
  • Fuse ops during conversion (--optimize)
  • Quantize to INT8 for CPU, FP16 for GPU
  • Prefer depthwise conv over standard conv
  • Minimize memory allocations (reuse tensors)
Runtime-Level
  • Set numThread to CPU core count
  • Prefer MNN_FORWARD_CPU for CPU-bound
  • Use NC4HW4 layout for convolutions
  • Reuse sessions for multiple inferences
  • Enable MNN_USE_GEMM for FC layers
Backend-Specific
  • CPU: AVX2, NEON enable → big speedup
  • Metal: Use MNN_METAL=ON, shared buffer
  • OpenCL: Tune work-group size
  • Vulkan: Use VMA-like memory allocator
  • Quant: Deploy with mnnquant tools
Memory
  • Avoid tensor copies (use copyFromHostTensor)
  • Pin host memory for GPU transfers
  • Batch inference for throughput
  • Use Session::releaseModel to free memory
  • Profile with MNN_DEBUG=1
