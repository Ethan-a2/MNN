Architecture Overview

Core Design

  • Graph Optimization + Heterogeneous Backend Scheduling
  • Two inference APIs:
    • Session API (low-level): Interpreter → createSession → runSession
    • Module API (high-level): Module::load → onForward(VARP)

Key Abstractions

  • Interpreter / Session: Model loading and inference session management
  • Backend / Execution: Hardware backend abstraction and per-op implementations
  • Tensor: Data container using NC4HW4 format for SIMD
  • Op / Schema: FlatBuffers-defined operator descriptors
  • Pipeline / Schedule: Graph execution pipeline

Tensor & Memory Format

enum DimensionType {
    TENSORFLOW,   // NHWC (TensorFlow)
    CAFFE,        // NCHW (Caffe)
    CAFFE_C4      // NC4HW4 (optimized)
};

// NC4HW4: channels packed by 4 for SIMD
// Example: for 32 channels, layout:
// N, C0..3, H, W | N, C4..7, H, W | ...
  • Device tensors allocate memory via backend
  • Host tensors use malloc directly
  • Supports half precision (FP16), int8 quantization

Op Implementation Pipeline

  1. Schema Definition – FlatBuffers .fbs files in schema/default/
  2. Shape Inference – source/shape/ computes output shapes from input shapes
  3. Geometry Decomposition (optional) – source/geometry/ breaks complex ops into simpler ones
  4. Backend Execution – Implement Execution for each backend (CPU/GPU/...).

Performance & Efficiency

  • Lightweight binaries:
    • iOS static library (armv7+arm64): ~12MB
    • Android core .so: ~800KB (armv7a, c++_shared)
    • Use MNN_BUILD_MINI to reduce ~25% size (fixed input size)
  • Quantization: FP16 / Int8 reduces model size 50-70%
  • Optimized compute:
    • Hand-tuned assembly for ARM / x64
    • Winograd convolution for 3x3–7x7 kernels
    • sdot / VNNI for ARM v8.2
  • GPU backends: Metal (iOS), OpenCL, Vulkan, CUDA

Interpreter API (C++)

// Create interpreter from model file
MNN::Interpreter* net = MNN::Interpreter::createFromFile("model.mnn");

// Configure session
MNN::ScheduleConfig config;
config.type = MNN_FORWARD_CPU;
config.numThread = 4;
config.backendType = MNN_FORWARD_CPU;

// Create session
MNN::Session* session = net->createSession(config);

// Get input & output tensors
MNN::Tensor* input  = net->getSessionInput(session);
MNN::Tensor* output = net->getSessionOutput(session);

// Set input data (host pointer)
input->copyFromHostTensor(&hostTensor);

// Run inference
net->runSession(session);

// Retrieve results
output->copyToHostTensor(&hostOutput);

Module API (Express)

#include "MNN/expr/Expr.hpp"
#include "MNN/expr/Module.hpp"

using namespace MNN::Express;

// Load model
std::shared_ptr module = Module::load("model.mnn");

// Create input variable (VARP)
auto input = _Input({1, 3, 224, 224}, NCHW);

// Forward pass
auto output = module->onForward({input});

// Get result as Tensor
std::shared_ptr result = output[0]->readMap();

Used by LLM / Diffusion workloads for dynamic graph construction.

Model Conversion

The tools/converter/ directory houses the converter frontends:

  • ONNX – 158 operators supported
  • TensorFlow / TensorFlow Lite – 178 operators supported
  • Caffe – 52 operators supported
  • PyTorch (Torchscript) – 163 operators supported

The converter performs graph optimizations (constant folding, operator fusion) and handles dynamic shapes, control flow, and multi-input/output models.
